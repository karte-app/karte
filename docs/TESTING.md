# 카르테 테스트

테스트는 네 단계로 나눠 진행했습니다. 아래 결과는 2026-11-15, Pleos Connect 에뮬레이터 v2.1.0(2560 x 1440)과 저장소의 release APK(`apk/Karte_Karte_release.apk`) 기준입니다.

| 단계 | 대상 | 방법 | 결과 |
| --- | --- | --- | --- |
| 단위 테스트 | 분류, 재현 조건 분석, 표시 문구, JSON 저장 형식 | JUnit (JVM) | 18건 통과 |
| 통합 테스트 | 기록 저장소 → JSON 파일 → 다시 읽기 → 재현 조건 분석 | JUnit (JVM, 실제 파일) | 5건 통과 |
| 시스템 테스트 | 에뮬레이터에 설치한 release APK 전체 흐름 | 자동 스크립트 (Virtual Console + adb) | 24개 확인 항목 통과 |
| 인수 테스트 | 기획서의 사용 시나리오 기준 | 시스템 테스트 결과 + 수동 확인 | 9개 중 7개 통과, 1개 일부 통과, 1개 일부 미확인 |

실차 테스트는 하지 못했습니다. 모든 결과는 에뮬레이터 기준입니다.

## 1. 단위 테스트

```
sh gradlew testDebugUnitTest
```

| 파일 | 건수 | 확인하는 것 |
| --- | --- | --- |
| `PatternAnalyzerTest` | 5 | 분류 규칙, 70% 기준, 값을 얻지 못한 기록은 근거에서 제외, 경고등은 종류별로 묶음, 1건은 분석하지 않음 |
| `LabelsTest` | 8 | 조향각 부호와 직진 범위, 얻지 못한 값은 "확인 불가", 스냅샷 요약 문구, 제한속도 표시, 경고등 15종, 경고등 이름 줄임 |
| `ModelsJsonTest` | 5 | 기록의 JSON 왕복, 없는 값은 저장하지 않음, 알 수 없는 분류·경로 값 처리, 속도·조향 구간 경계 |

## 2. 통합 테스트

단위 테스트와 같은 명령으로 함께 실행됩니다. `StoreAnalysisIntegrationTest` 5건입니다.

- 차량 SDK와 화면을 뺀 나머지(`RecordStore`, JSON, `Samples`, `PatternAnalyzer`)를 실제 파일로 이어서 확인합니다.
- 시연 영상과 같은 순서로 기록을 넣고(음성 1건, 경고등 자동 기록 1건, 예시 5건) 앱을 다시 켠 것처럼 저장소를 새로 열었을 때, 화면에 나온 것과 같은 결과가 나오는지 확인합니다: 소음 증상 4건(저속 4/4, 브레이크 4/4, 우회전 4/4, 기어 D 4/4, 같은 장소 3/4), 타이어 공기압 경고등 2건(기어 D 2/2).
- 기록 삭제, 깨진 파일에서의 복구, 단골 정비소 저장과 삭제를 확인합니다.
- 저장 위치와 설정 저장소만 제공하는 테스트용 `Context`를 씁니다. 기기의 `SharedPreferences` 구현 자체는 대상이 아닙니다.

## 3. 시스템 테스트

```
adb forward tcp:8088 tcp:8088
python3 tests/system/system_test.py --install apk/Karte_Karte_release.apk
```

Virtual Console의 HTTP 인터페이스로 차량 상태를 바꾸고, adb로 화면을 누르고, 화면에 보이는 글자를 읽어 확인합니다. 앱 권한은 미리 허용해야 합니다(README의 실행 방법).

| 단계 | 조작 | 확인 |
| --- | --- | --- |
| S0 | 앱 실행, 기록 비우기 | 앱이 뜨고 기록 0건 |
| S1 | 기어 P, 정지 | 기어 P·시속 0km 표시, 직접 입력·예시 기록·리포트·정비소 안내 버튼 표시 |
| S2 | 기어 D, 시속 24km | 주행 화면 전환, 목록·입력·리포트·정비소 버튼 숨김, 증상 말하기 버튼 유지 |
| S3 | 브레이크, 조향각 -48(콘솔 입력) | 브레이크 밟는 중, 핸들 오른쪽 48°, 시속 22km |
| S4 | TPMS 경고등 켜기 | 조작 없이 기록 1건, 안내 문구, 켜진 동안 중복 기록 없음 |
| S5 | 기어 P | 목록 다시 표시, 자동 기록에 스냅샷 요약 |
| S6 | 예시 기록 | 총 6건, 반복 조건(소음 3건 3/3, TPMS 경고등 2건 2/2), "예시" 표시 |
| S7 | 기록 누르기 | 상세에 스냅샷 항목, 주행 모드는 "확인 불가" |
| S8 | 리포트 | 반복 조건과 전체 기록 |
| S9 | 리포트를 연 채 기어 D | 팝업이 닫히고 주행 화면 |
| S10 | TPMS 끄기, 전체 삭제 | 상태 칸 "없음", 기록 0건 |

결과: 24개 확인 항목 통과(연속 2회 실행). 실행 중 앱 비정상 종료 로그는 없었습니다.

자동화하지 못한 것:

- 음성 인식: 사람이 말해야 해서 스크립트에 넣지 못했습니다. 아래 인수 테스트 A1에서 수동으로 확인했습니다.
- 길 안내: 에뮬레이터 내비게이션이 경로 탐색 오류를 반환합니다.
- 세로 창과 야간 모드: 수동으로 확인했습니다.

## 4. 인수 테스트

기획서 "4. 주요 사용 시나리오"와 설계 원칙을 기준으로 삼았습니다.

| 번호 | 기준 | 확인 방법 | 결과 |
| --- | --- | --- | --- |
| A1 | 주행 중 버튼을 한 번 누르고 말하면 문장과 그 순간의 차량 상태가 저장되고 음성으로 확인해 준다 | 수동. 호스트 마이크로 말함. 시연 영상 0:12 | 통과. 음성 안내는 재생 요청 로그로 확인(소리 녹음 없음) |
| A2 | 같은 증상이 쌓이면 공통 조건을 건수와 함께 보여 준다 | 통합 테스트, 시스템 S6 | 화면 표시 통과(예시 데이터 기준). 세 번째 기록에서 나오는 음성 안내는 미확인 |
| A3 | 경고등이 켜지면 말하지 않아도 그 순간을 기록한다 | 시스템 S4, 시연 영상 0:20 | 통과 |
| A4 | 정차하면 기록 목록과 반복 조건이 다시 보인다 | 시스템 S5, S6 | 통과 |
| A5 | 단골 정비소로 길 안내를 요청하고 리포트를 보여 줄 수 있다 | 수동(정비소 등록, 안내 요청), 시스템 S8 | 일부 통과. 리포트와 정비소 등록은 통과, 길 안내 요청은 내비게이션까지 전달되지만 에뮬레이터가 경로 탐색 오류를 반환 |
| A6 | 주행 중에는 음성 기록 외의 조작을 숨긴다 | 시스템 S2, S9 | 통과 |
| A7 | 차량이 주지 않은 값은 추정하지 않고 "확인 불가"로 남긴다 | 단위 테스트, 시스템 S7 | 통과 |
| A8 | 기록을 차량 밖으로 보내지 않는다 | 코드 확인: 기록은 앱 내부 파일에만 저장, 앱 코드에 네트워크 호출 없음, 음성은 ON_DEVICE 모드 | 통과(코드 확인). 단, Pleos SDK가 선언한 INTERNET 권한이 APK에 병합되어 있어 권한 수준에서 막혀 있지는 않음. 통신 내용을 측정한 것은 아님 |
| A9 | 주간·야간 모드, 가로·세로 창에서 화면이 깨지지 않는다 | 수동(야간 전환, 내비게이션과 화면 분할 841 x 1210) | 통과 |

## 아직 하지 않은 테스트

- 실차 테스트
- 실제 주행으로 쌓인 기록에서의 재현 조건 분석 (지금은 예시 데이터)
- 장시간 실행, 기록이 많을 때의 성능
- 화면(Activity)과 차량 SDK 연결부의 계측 테스트(androidTest). 지금은 시스템 테스트가 이 부분을 대신 확인합니다.
